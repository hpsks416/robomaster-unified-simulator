## 1. 版本说明

这个版本采用**理想云台控制**，重点是把“看到什么”和“目标往哪里转”稳定地交给视觉算法验证，而不是逐行复现电控固件。

仿真器收到视觉端给出的目标角后，默认按有限角速度跟随，并对角度做回绕和俯仰限位：

- `GIMBAL <yaw> <pitch>` 和 `GIMBAL_VISION <state> <yaw> <pitch>` 都可以改变相机云台；
- 默认最大角速度约 `3 rad/s`，可以通过环境变量调整；
- 相机位置保持不变，只改变相机姿态；
- 不模拟电机电流环、CAN 总线、CRC、机械间隙、1 ms 控制任务和电控模式切换。

因此，本版适合调试检测、PnP、目标跟踪、弹道预测和视觉控制闭环，**不适合**用来评估电控固件本身的控制效果。

确实需要一个“指哪到哪”的理想执行机构做对照时，可以设置：

```bash
DAEDALUS_GIMBAL_MODE=direct ./run_host.sh
```

此时两参数云台报文会直接到达目标角，不再做渐进跟随。日常联调建议保留默认的 `vision` 模式。

本说明整理时对应版本为 `Bata-3.2.1`。完整版本记录见仓库中的 `version.txt`。

## 2. 二次开发内容

- 常用自瞄场景不再依赖完整比赛场地，默认使用程序生成式平地；另保留 `base`、`rmuc2026` 两个整场模型查看场景
- 将整车底盘、大小符、前哨站和飞镖拆成独立场景，通过一个配置文件切换
- 加入 TCP、UDP 图像流，以及同机低延迟的 POSIX 共享内存原始图像流
- 加入飞镖视觉仿真，包含四片舵面、气动力、发射物理和第一人称相机
- 飞镖场景只负责物理和舵机执行，不内置制导律，控制算法通过接口下发舵角
- 支持视觉端回发 `FIRE`、`RESET`、`GYRO`、`GIMBAL` 和 `DART` 指令
- 支持导出装甲板与灯条位置真值，便于做检测、PnP 和跟踪回归

场景选择、通信方式和可选的相机距离都集中在：

```text
simulator/config/camera.yaml
```

最常用的配置如下：

```yaml
scenario: armor_chassis
protocol: tcp

# 可选：相机到部件中心的水平距离，单位米
# distance: 5.5
```

支持的场景：

| `scenario` | 内容 |
|---|---|
| `energy_rune` | 能量机关，一面小符、一面大符 |
| `energy_small` | 能量机关，两面都按小符运行 |
| `energy_large` | 能量机关，两面都按大符运行 |
| `armor_chassis` | 整车与装甲板，默认场景 |
| `outpost` | 前哨站及其旋转装甲板 |
| `guided_dart` | 制导飞镖与打击基地 |
| `base` | 直接查看旧版飞镖赛场模型 |
| `rmuc2026` | 直接查看 RMUC2026 官方整场模型 |

修改 `scenario` 后需要重启模拟器。也可以用 `DAEDALUS_SCENARIO` 临时覆盖，例如：

```bash
DAEDALUS_SCENARIO=outpost ./run_host.sh
```

## 4. 环境依赖

### 4.1 硬件与系统

- 推荐使用带独立显卡或可用核显的 Linux / Windows 主机
- 同时运行视觉算法时，建议至少 8 GiB 内存；只有 4 GiB 时把编译任务数设为 `1`
- 模拟器依赖 Vulkan、Metal 等图形后端，CPU 软件渲染也能启动，但高分辨率帧率会明显下降
- 共享内存模式要求模拟器和视觉端运行在**同一台机器**上
- 远程运行时，接收端要能访问模拟器主机的 `7666`、`7667` 端口；使用 UDP 时还要放行 `7669`，读取能量机关遥测时再放行 `7668`

### 4.2 Rust

模拟器使用 Rust Edition 2024。建议安装当前稳定版 Rust，不要使用过老的发行版仓库中的旧工具链。

Linux / macOS：

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env"
cargo --version
```

Windows 可以通过 rustup 安装，并同时安装 Visual Studio Build Tools 的“使用 C++ 的桌面开发”组件：

```powershell
winget install Rustlang.Rustup
cargo --version
```

国内网络下载 Rust 组件较慢时，可以在安装前设置镜像，例如：

```bash
export RUSTUP_DIST_SERVER=https://mirrors.tuna.tsinghua.edu.cn/rustup
```

### 4.3 Linux 依赖

Ubuntu 22.04 / Debian 可先安装编译和图形运行库：

```bash
sudo apt update
sudo apt install -y \
  build-essential pkg-config cmake \
  libwayland-dev libxkbcommon-dev libasound2-dev \
  libvulkan1 mesa-vulkan-drivers
```

建议再安装 `lld`，减少 Bevy 链接时的内存峰值：

```bash
sudo apt install -y lld
```

`cmake` 和 C 工具链用于可选的 `fast-jpeg` 编码器。如果编译失败，启动脚本会自动退回纯 Rust 编码器；也可以显式关闭它：

```bash
DAEDALUS_FAST_JPEG=0 ./run_host.sh
```

安装 `libjpeg-turbo`、`nasm` 可以进一步缩短 JPEG 编码时间，但它们不是启动模拟器的硬性条件。

### 4.4 macOS 依赖

```bash
xcode-select --install
brew install cmake
```

如果系统没有安装 rustup，再执行上一节的 Rust 安装命令。

### 4.5 接收示例与辅助脚本依赖

编译 `example/` 需要 CMake、C++ 编译器、pkg-config、OpenCV 和 yaml-cpp。

Ubuntu：

```bash
sudo apt install -y cmake g++ libopencv-dev libyaml-cpp-dev
```

macOS：

```bash
brew install cmake opencv yaml-cpp
```

Python 3 仅用于调试、UDP 抓包、飞行日志分析和曲线绘制等辅助脚本，不是模拟器运行的必需项。

## 5. 最短启动路径

先启动模拟器：

```bash
cd simulator_system/simulator
./run_host.sh
```

第一次启动会下载并编译依赖，通常需要几分钟。之后会保留 `target/` 缓存，重新启动会快很多。

如果从压缩包解压后 Shell 提示权限不足：

```bash
chmod +x run_*.sh
./run_host.sh
```

启动日志中应能看到类似下面的信息：

```text
[sim] exe=... scenario=ArmorChassis ... capture=1440x1080@30 protocol=tcp
Simulator command server listening on 0.0.0.0:7667
```

说明模拟器已经启动，图像端口为 `7666`，控制指令端口为 `7667`。

另开一个终端验证接收：

```bash
cd simulator_system/example
cmake -S . -B build
cmake --build build -j4
./build/sim_receiver_example ../config/simulator.yaml
```

示例会持续接收图像，每 30 帧在当前目录保存一张 `frame_XXXX.jpg`，收到 300 帧后自动退出。能保存出图片，说明模拟器到接收端的图像链路已经接通。

## 6. 启动脚本怎么选

所有脚本都在 `simulator/` 目录下执行。不要在仓库根目录直接运行 `./run_host.sh`。

| 脚本 | 适用环境 | 默认行为 |
|---|---|---|
| `run_host.sh` | Linux / macOS 本机调试 | `1440x1080@30`、JPEG 95、显示预览窗口 |
| `run_host.bat` | Windows CMD 本机调试 | Release 构建、显示预览、采集默认 `640x480@30` |
| `run_host.ps1` | Windows PowerShell | 与 `run_host.bat` 类似 |
| `run_remote.sh` | 模拟器与视觉端分开运行 | `1440x1080@20`、JPEG 80、关闭预览 |
| `run_nuc.sh` | Linux NUC / 无显示器服务器 | 检查图形会话、GPU、锁屏，默认关闭远端云台控制 |
| `run_vm.sh` | 没有 GPU 的 Linux 虚拟机 | 强制软件 Vulkan，降低窗口和采集开销 |

### 6.1 本机启动

```bash
cd simulator
./run_host.sh
```

Windows CMD：

```bat
cd simulator
run_host.bat
```

Windows PowerShell：

```powershell
cd simulator
.\run_host.ps1
```

Windows 启动脚本为了兼容较弱的机器，默认采集尺寸是 `640x480`。如果你使用按 `1440x1080` 标定的视觉算法，启动前要统一尺寸：

```bat
set DAEDALUS_CAPTURE_WIDTH=1440
set DAEDALUS_CAPTURE_HEIGHT=1080
run_host.bat
```

### 6.2 两台机器运行

模拟器主机执行：

```bash
cd simulator
./run_remote.sh
```

接收端修改 `example/config/simulator.yaml`：

```yaml
host: "192.168.1.100"
port: 7666
```

将 `host` 换成模拟器所在主机的实际 IP。远程预设使用 `JPEG 80 + 20 FPS`，在普通无线网络和百兆链路上更稳。需要临时看预览时：

```bash
DAEDALUS_PREVIEW=1 ./run_remote.sh
```

链路状态不好时优先降低画质，而不是降低采集分辨率：

```bash
DAEDALUS_JPEG_QUALITY=70 DAEDALUS_CAPTURE_FPS=15 ./run_remote.sh
```

### 6.3 NUC / 服务器后台运行

```bash
cd simulator
./run_nuc.sh          # 前台运行
./run_nuc.sh -d       # 后台运行，日志写入 nuc_sim.log
```

还可以指定小陀螺转速和相机到目标的水平距离：

```bash
./run_nuc.sh 3.0 6.0
```

第一个参数是 `rad/s`，第二个参数是米。`run_nuc.sh` 会自动设置 `XDG_RUNTIME_DIR`，优先寻找 Wayland/X11 图形会话，并检查 `/dev/dri` 和桌面锁屏状态。

注意：`run_nuc.sh` 默认设置 `DAEDALUS_GIMBAL_CONTROL=0`，此时视觉端发送的云台指令会被忽略，相机固定在开机位姿。要让视觉端控制云台，需要执行：

```bash
DAEDALUS_GIMBAL_CONTROL=1 ./run_nuc.sh -d
```

不要在有 Intel 核显的机器上使用 `xvfb-run`。Xvfb 通常没有 DRI3，可能导致 `No supported formats for surface`；即使退回软件渲染，帧率也会很低。

### 6.4 虚拟机软件渲染

没有可用 GPU 时使用：

```bash
cd simulator
./run_vm.sh
```

该脚本设置 `WGPU_FORCE_FALLBACK_ADAPTER=1`、`LIBGL_ALWAYS_SOFTWARE=1`，并把采集帧率降到 `15 FPS`。软件渲染下应优先降低帧率，不要为了提速修改 `DAEDALUS_CAPTURE_WIDTH/HEIGHT`，否则视觉端内参和 PnP 尺度会不匹配。

### 6.5 手动编译

启动脚本本质上是在执行 Release 构建并运行 `daedalus`。需要自己控制 feature 时可以使用：

```bash
cd simulator
cargo build --release --no-default-features --features rune-only,tcp-only
./target/release/daedalus
```

直接运行二进制时，采集尺寸的兜底值较小，建议显式设置：

```bash
DAEDALUS_CAPTURE_WIDTH=1440 \
DAEDALUS_CAPTURE_HEIGHT=1080 \
DAEDALUS_CAPTURE_FPS=30 \
./target/release/daedalus
```

## 7. 按键控制

不同场景下，同一个按键可能有不同含义。最常用的是下面这一组：

| 按键 | 功能 |
|---|---|
| `W` / `A` / `S` / `D` | 整车场景中控制整车相对相机前后左右移动 |
| `Space` | 从当前相机位置发射一颗弹丸 |
| `R` | 打开或关闭整车小陀螺 |
| `E` | 复位相机、整车、底盘、云台和运动状态，并恢复启动时的小陀螺状态 |
| `F3` | 在自由视角、机器人视角和第三人称跟随之间切换 |
| 鼠标 | 自由视角下旋转镜头 |

复位功能与视觉端发送 `RESET` 的效果一致。连续做多轮测试时，建议每轮开始先复位，否则上一次的相机姿态和底盘状态会带到下一次。

启动脚本默认按 `rune-only,tcp-only` 构建，正常自瞄场景会锁定鼠标旋转和 `F3`，防止调试时误碰镜头。`base`、`rmuc2026` 两个整场模型查看场景不受此限制。

如果需要在普通场景里自由观察，不要只设置 `DAEDALUS_RUNE_ONLY=0`，因为已编译进二进制的 `rune-only` feature 仍然会锁定视角。应重新构建一个不带该 feature 的版本：

```bash
cd simulator
cargo build --release --no-default-features --features tcp-only
DAEDALUS_CAPTURE_WIDTH=1440 DAEDALUS_CAPTURE_HEIGHT=1080 \
  ./target/release/daedalus
```

进入自由视角后，`W/A/S/D` 用于移动相机；此时它不再用于移动整车。

### 7.1 前哨站场景

前哨站默认以 `0.8π rad/s` 旋转，只旋转上部装甲板支架，不旋转塔座和立柱。转速和方向可以覆盖：

```bash
DAEDALUS_OUTPOST_SPEED=0 ./run_host.sh          # 静止
DAEDALUS_OUTPOST_SPEED=-2.5133 ./run_host.sh    # 反向 0.8π rad/s
```

按 `E` 会把前哨站旋转相位恢复到启动状态。

### 7.2 飞镖场景

| 按键 | 功能 |
|---|---|
| `F` | 发射飞镖 |
| `R` | 复位飞镖和舵面 |
| `V` | 开关右下角第三人称跟随镜头 |
| `T` | 开始 / 停止自动连打 |

飞镖场景的 TCP 图像始终来自机头第一人称相机。`V` 只改变本地预览布局，不会把画中画或第三人称画面发给视觉端。

飞镖靶运动模式在 `guided_dart/config/simulator.toml` 中设置：

```toml
[base.target_motion]
mode = "random_fixed"   # fixed / random_fixed / random_moving / end_moving
```

对应模式：

| 模式 | 含义 |
|---|---|
| `fixed` | 靶始终静止 |
| `random_fixed` | 场景加载后随机移动一次，检测时间窗结束后回位 |
| `random_moving` | 发射时移动一次，命中或超时后再移动 |
| `end_moving` | 发射后等待一段时间再移动 |

也可以用 `DAEDALUS_TARGET_MOTION_MODE` 临时覆盖。

## 8. 图像传输方式

模拟器默认同时保留 TCP 图像服务，UDP 和共享内存是按需增加的通道。所有模式下，控制指令仍然走 TCP `7667`。

| 方式 | 默认端口 | 使用场景 | 特点 |
|---|---:|---|---|
| TCP | `7666` | 本机或跨机 | 单帧数据完整，慢客户端会跳帧，可能受重传和队头阻塞影响 |
| UDP | `7669` | 跨机、无线网络 | 延迟低，链路拥塞时丢帧而不是卡住 |
| SHM | POSIX 名称 | 模拟器与视觉端同机 | 传原始像素，跳过 JPEG、分片和网络解码 |

### 8.1 TCP

`camera.yaml` 写 `protocol: tcp` 即可。每个数据帧是：

```text
40 字节大端帧头（版本 2）+ JPEG 图像
```

帧头以 `DAED` 开头。接收示例和 `API.md` 已经处理了版本 1 的旧 32 字节包头兼容。

### 8.2 UDP

开启 UDP 后，TCP 那一路不会关闭，两边可以同时对比：

```yaml
scenario: armor_chassis
protocol: udp
```

也可以临时覆盖：

```bash
DAEDALUS_UDP=1 ./run_host.sh
```

接收端在 `example/config/simulator.yaml` 中写：

```yaml
protocol: udp
udp_port: 7669
```

UDP 使用分片传输，一帧缺片就整帧丢弃。接收端应始终处理最新帧，不要积压旧帧。

### 8.3 共享内存

只有模拟器和视觉端在同一台机器上才能使用。配置：

```yaml
scenario: armor_chassis
protocol: shm
shm_name: daedalus_frames
```

或者：

```bash
DAEDALUS_SHM=1 \
DAEDALUS_SHM_NAME=daedalus_frames \
./run_host.sh
```

共享内存使用固定的 256 字节头和 3 个图像槽，图像是本机原始 RGBA/BGRA 像素。读端应检查 `magic`、`version`、尺寸、`row_stride`、`pixel_format` 和提交序号；只有前后两次 `commit_seq` 相同且为偶数时，才能接受该帧。

只有 SHM 读者时，模拟器不会执行 JPEG 编码；如果同时还有 TCP 客户端，则会同时发布 SHM 和 JPEG。完整头字段和读取流程见 `API.md` 的共享内存章节。

Windows 下优先使用 TCP 或 UDP，不建议把 POSIX 共享内存作为跨平台接口。

## 9. 视觉端控制接口

控制指令通过 TCP `7667` 发送，每条文本指令以换行结束。

```text
GIMBAL <yaw> <pitch>
GIMBAL_VISION <state> <yaw> <pitch>
FIRE
RESET
GYRO 0
GYRO 1
DART <pitch> <yaw> <roll>
```

### 9.1 云台

```text
GIMBAL 0.12 -0.05
```

- `yaw` 和 `pitch` 的单位都是弧度
- `yaw` 正方向向右，`pitch` 正方向向上
- 这是绝对目标角，重复发送会覆盖上一目标，不会累加
- 默认 `vision` 模式下按有限角速度逐步到达
- 设置 `DAEDALUS_GIMBAL_MODE=direct` 后瞬时到达
- 俯仰默认限制在 `±80°`，可用 `DAEDALUS_GIMBAL_PITCH_MIN/MAX` 改为非对称限位

```text
GIMBAL_VISION 0 0.12 -0.05
GIMBAL_VISION 1 0.12 -0.05
```

`state=0` 表示视觉暂不驱动云台，保持当前角度；`state=1` 表示视觉接管并跟随目标角。理想云台版里 `state=2` 的“接管”语义与 `state=1` 相同，**不会自动发射**，需要另外发送 `FIRE`。

默认跟随参数：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `DAEDALUS_GIMBAL_YAW_DEADBAND` | `0.002 rad` | 水平死区 |
| `DAEDALUS_GIMBAL_PITCH_DEADBAND` | `0.003 rad` | 俯仰死区 |
| `DAEDALUS_GIMBAL_YAW_FINE_RATE` | `3.0 rad/s` | 水平细调最大角速度 |
| `DAEDALUS_GIMBAL_YAW_COARSE_RATE` | `3.0 rad/s` | 水平粗调最大角速度 |
| `DAEDALUS_GIMBAL_PITCH_RATE` | `3.0 rad/s` | 俯仰最大角速度 |
| `DAEDALUS_GIMBAL_FINE_GAIN` | `1.0` | 进入死区后的收敛增益 |

如果 `DAEDALUS_GIMBAL_CONTROL=0`，所有云台指令都会被忽略，但 `FIRE` 和 `RESET` 仍然有效。

### 9.2 射击、复位和小陀螺

```text
FIRE
RESET
GYRO 1
GYRO 0
```

- `FIRE`：发射一颗弹丸；飞镖场景中表示发射飞镖
- `RESET`：等价于按 `E`
- `GYRO 1`：开启整车小陀螺
- `GYRO 0`：关闭整车小陀螺

远程主机没有键盘时，可以用这些文本命令配合脚本控制。

### 9.3 飞镖舵角

```text
DART <pitch> <yaw> <roll>
```

三个参数都是弧度，直接写入舵面期望角。`SERVO` 是同义命令。仿真器内部不做制导律，停止收到新指令超过 `servo_pid.command_timeout_secs` 后，舵面回到中立。

飞镖场景还会按 `guided_dart/config/simulator.toml` 中的 `state_telemetry_hz` 回推 `STATE` 状态，供视觉端做闭环解算。

## 11. 场景资源与数据

`armor_chassis` 和 `outpost` 场景默认导出：

- `dataset.csv`：装甲板中心在相机坐标系下的位置、颜色、距离、时间和板号
- `light_bars.csv`：每块装甲板两根灯条的位置、端点、时间和编号

整车场景每帧导出 4 行装甲板和 8 行灯条；前哨站每帧导出 3 行装甲板和 6 行灯条。

绘图：

```bash
cd simulator
python3 plot_results.py dataset.csv
python3 plot_results.py dataset.csv --select 0
```

飞镖场景还可以记录飞行日志，路径在 `guided_dart/config/simulator.toml` 中配置：

```toml
[vision]
flight_csv_path = "flight_log.csv"
```

## 12. 常见问题

### 启动时报 `cargo: command not found`

重新打开终端，或执行：

```bash
source "$HOME/.cargo/env"
```

### Linux 编译时报 `wayland-client.pc not found`

缺少 Wayland 开发包：

```bash
sudo apt install -y libwayland-dev libxkbcommon-dev
```

### 编译或链接时内存不足

降低并行编译任务数：

```bash
CARGO_BUILD_JOBS=1 ./run_host.sh
```

Linux 下建议安装 `lld`。已经安装 `sccache` 时，启动脚本会自动使用它。

### 能看到窗口，但接收端收不到图

依次检查：

1. 接收端 `host` 是否是模拟器主机的正确 IP
2. 防火墙是否放行 `7666`，使用 UDP 时是否放行 `7669`
3. 模拟器日志里是否出现端口绑定失败
4. `DAEDALUS_PREVIEW` 是否被误当成图像开关；预览关闭不影响 TCP 采集
5. 是否真的启动了带 `tcp-only` feature 的程序

同一台机器只能稳定运行一个模拟器实例。端口被占用时先停止旧进程：

```bash
pkill -f 'target/release/daedalus'
```

### 画面帧率很低

- 确认 `/dev/dri` 中存在 GPU 设备
- 不要在会锁屏的桌面会话中长期运行
- 不建议用 `xvfb-run` 运行有 GPU 的主机
- 先降低 `DAEDALUS_CAPTURE_FPS` 或 `DAEDALUS_JPEG_QUALITY`
- 保持 `DAEDALUS_CAPTURE_WIDTH/HEIGHT` 与视觉端标定一致
- 虚拟机使用 `run_vm.sh`，并接受软件渲染的帧率上限

### 按 `F3` 没有反应

启动脚本默认启用了 `rune-only`，会锁定普通场景的相机输入。可以切换到 `base` / `rmuc2026` 查看整场模型，或者按第 7 节重新构建不带 `rune-only` 的版本。

### 远程主机上视觉端无法转动云台

`run_nuc.sh` 默认关闭远端云台控制。使用：

```bash
DAEDALUS_GIMBAL_CONTROL=1 ./run_nuc.sh
```

如果不希望相机被视觉端控制，保持默认 `0` 即可。

### 图像尺寸和视觉端内参对不上

优先检查启动日志里的 `capture=`。视觉端如果按 `1440x1080 / 41°` 标定，就必须使用同样的采集尺寸和 FOV。窗口大小只是预览，不能替代 `DAEDALUS_CAPTURE_*`。
